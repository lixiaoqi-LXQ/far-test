# RAF Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task. The user has supplied and authorized `design.md`; execute directly in this directory.

**Goal:** Implement the exact RAF v1 format, prove recovery and durability behavior, and report measured performance against fio.

**Architecture:** One synchronous, mutex-protected writer uses writev and a periodic fdatasync thread. Readers share an immutable index and a read-only mmap; recovery scans the valid prefix under an exclusive flock.

**Tech Stack:** Linux, C++20, CMake, pthreads, dependency-free tests, fio 3.36, Python 3 benchmark orchestration.

**Spec:** `design.md`, with delivery requirements from `task.md`.

## Global Constraints

- Header is 16 bytes; records are `[u32 len][u32 len_crc][payload][u32 payload_crc]`; footer is `8*N+4` bytes.
- All integers are little endian; every checksum is CRC32C.
- No queue, additional format metadata, direct I/O in RAF, index cache, or implicit recovery.
- Footer must be synchronized before publishing and synchronizing the new header.
- A writer never reopens an existing archive to append. Opening must not truncate existing data.
- Same-file flock conflicts return Busy without waiting; independently opened readers are allowed.
- Payload views and iterators cannot outlive their reader. Destruction must not race with API calls.

## Review Focus

1. A Busy writer must not modify an existing archive or the archive held by another writer.
2. Short writes crossing record boundaries and EINTR must not publish incomplete IDs.
3. Sync must never overstate durability when append overlaps fdatasync, and must not hold the append mutex during the syscall.
4. Malicious footer offsets must be rejected before mmap pointer arithmetic; full validation must detect length corruption missed by hot reads.
5. Recovery must stream large payloads, stop at the first invalid record, and reject unrecognizable versions without modifying the file.
